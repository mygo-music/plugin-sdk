# 07 · 安全模型

插件是第三方代码,市场对任何人开放提交。设计假设是:**插件可能有恶意或有 bug,而用户不应该为此承担风险。**

## 7.1 威胁与对策

| 威胁 | 对策 |
|---|---|
| 读写用户文件、环境变量、启动进程 | WASM 沙箱:没有文件系统预打开目录、没有环境变量与参数、没有进程 API(§3.1) |
| 访问任意网络、把数据发往任意服务器 | 网络只能走宿主函数 `http.do`;主机必须在 `network.hosts` 内(§7.2) |
| 把宿主当作跳板访问内网(SSRF) | 解析后的 IP 检查:拒绝环回、私网、链路本地、CGNAT、组播、元数据地址(§7.3) |
| 读取其他插件的会话 | cookie 罐、kv、secret 全部按插件 ID 隔离;API 里没有「指定插件」的参数 |
| 通过返回的流/封面地址让宿主访问任意主机 | 宿主获取的资源也受 `media.hosts` 限制(§7.2),并且不带 cookie |
| 伪造登录界面钓取密码 | 登录界面总是宿主的原生控件;插件只描述字段(06 号文档) |
| 拖垮或崩溃宿主 | 内存、时间、响应体、并发、日志速率都有上限(§3.7);超限只丢弃该实例 |
| 更新后偷偷扩大权限 | 新增主机、`local`、新能力时必须用户重新确认(§7.5) |
| 恶意更新(供应链) | 市场对每个版本固定 sha256;发布必须带 GitHub 构建来源证明;可吊销(§7.6) |
| 输出里夹带脚本 | 所有插件文本按纯文本渲染;宿主不解析 HTML/Markdown;`javascript:` 等非 http(s) 图片地址一律拒绝 |

## 7.2 网络权限

两类权限,故意分开:

| | `network.hosts` | `media.hosts` |
|---|---|---|
| 谁发请求 | 插件(通过 `http.do`) | 宿主(下载封面、头像、音频流) |
| 带 cookie | 是(插件的 cookie 罐) | **否** |
| 内容 | API | 图片、音频 |

分开的好处:封面、音频的 CDN 域名通常又多又杂(`*.music.126.net`),放进 `network.hosts` 会让插件能带着会话 cookie 向这些域名发请求;分开后,插件的会话 cookie 只会发给声明的 API 主机。

匹配规则(`example.com` / `*.example.com` / `http://example.com`)见 [02 号文档](02-manifest.md#24-权限)。**每一次**请求以及**每一次重定向**都重新匹配。

## 7.3 IP 防护

宿主在发起任何插件触发的连接前,解析主机名,并在**拨号时**检查实际 IP(防 DNS 重绑定):

- 拒绝:`127.0.0.0/8`、`::1`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`(含云元数据)、`100.64/10`、`fc00::/7`、`fe80::/10`、组播、未指定地址。
- 例外:manifest 的 `network.local: true`,或设置项里 `grant_network: true` 由用户亲手输入的主机。这两种情况下安装/保存时都有醒目提示。
- 不使用系统代理里对内网的绕过规则。

## 7.4 数据隔离与存储

```
<UserData>/plugins/<id>/<version>/      包内容(manifest.json、plugin.wasm、icon.png)
<UserData>/plugins/<id>/data/kv.json    kv 存储(≤ 1 MiB)
钥匙串  条目名 "mygo-music/plugin/<id>/<key>"   secret 与 cookie 罐
```

- 开发构建(`mygo.IsDev()`)用私有文件代替钥匙串,避免每次重新签名都弹钥匙串授权,沿用现有做法。
- 卸载插件时询问是否同时删除它的数据与会话;默认删除。
- **宿主不会把任何插件数据上传到任何地方。**

## 7.5 权限变更与同意

| 事件 | 行为 |
|---|---|
| 首次安装(市场) | 对话框列出:名称、作者、来源层级(官方/社区)、能力、**网络主机**、是否访问局域网 |
| 首次安装(URL) | 同上,外加醒目提示「此插件未经市场审核」,并展示仓库地址 |
| 更新,权限不变 | 静默更新(用户可在设置中改为手动) |
| 更新,新增主机 / `local` / 新能力 | 对话框展示**差异**,用户同意前继续使用旧版本 |
| 更新,权限缩小 | 静默更新 |

## 7.6 供应链

**对每个版本:**

1. **sha256 固定。** 市场的 `index.json` 记录每个版本的 `.mgp` sha256;宿主下载后校验,不一致则拒绝并报告。
2. **构建来源证明。** 市场要求 `.mgp` 带 [GitHub 构建来源证明(artifact attestation)](https://docs.github.com/en/actions/security-for-github-actions/using-artifact-attestations),证明它是由该仓库的指定工作流在指定提交上构建出来的。登记处的 CI 用 `gh attestation verify` 验证,SDK 模板的发布工作流默认就会生成。
3. **可吊销。** `index.json` 的 `revoked` 列出被撤下的版本范围;宿主刷新索引时发现已安装的插件被吊销,**立即停用**并提示用户。

**URL 安装**不经过登记处,因此没有 1、3 的保护。宿主会校验 `.mgp` 的结构与 manifest,显示权限,并**强提示**风险。宿主在 v1 不自己验证来源证明(见 §7.7),所以 URL 安装的包不会被标为「已验证」。

## 7.7 残余风险(明确写出来)

沙箱和权限不能解决的:

- 插件可以**对声明的主机**发送它能访问到的任何数据——包括它自己的会话。所以 `network.hosts` 要尽量窄,评审也会盯这一项。
- 插件可以返回误导性的内容(假歌名、假推荐)。市场的人工评审和社区举报是对策,技术上无解。
- 来源服务本身的行为(登录风控、封号、条款)不由宿主控制。用户用自己的账号使用第三方客户端的风险由用户承担;插件作者有责任在描述里写明。
- 宿主的 wazero 运行时、系统 TLS、解码库自身的漏洞。依赖更新是宿主的日常职责。
- **市场索引本身没有签名。** 宿主只核对「下载到的包」与「索引里记录的 sha256」是否一致,**不自己验证来源证明**——那是登记处 CI 在收录时做的。所以如果有人能篡改索引(例如拿到登记处仓库或 `mygo-music` 组织的写权限),就能把某个插件的下载地址和 sha256 一起换掉,宿主会照单安装。这一层的保护是账户安全:对 `mygo-music` 组织强制两步验证、收紧登记处仓库的写权限与分支保护。是否让宿主在安装时也验证来源证明,留待实现时评估。

## 7.8 报告漏洞

通过各仓库 `SECURITY.md` 里的私密渠道报告(GitHub Security Advisories),不要开公开 issue。(各仓库建立时补上。)
