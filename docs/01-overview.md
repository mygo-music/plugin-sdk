# 01 · 总览与决策

## 1.1 目标

- 把「音乐来源」从播放器里拆出来:登录、搜索、歌单、取流、歌词、评论等由插件提供。
- 任何人都能写插件:有稳定的契约、脚手架、测试工具,发布流程自动化。
- 用户装插件不必担心安全:插件在沙箱里运行,只能访问它声明过的域名,看不到其他插件的数据。
- 插件一次构建,三个平台(macOS / Windows / Linux)通用。
- 宿主保持原生界面。插件不自绘 UI,只提供数据,宿主按能力渲染。

## 1.2 非目标(v1)

- 插件自定义界面、主题、可视化(留给以后的插件种类)。
- 插件替换播放内核或解码器。宿主解码 MP3 与 FLAC;新格式由宿主升级时加入。
- 一个插件同时充当多个来源。一个插件就是一个来源。
- 跨来源的歌词、元数据互补(见 §1.8)。

## 1.3 术语

| 术语 | 含义 |
|---|---|
| 宿主(host) | MyGo 音乐应用本身 |
| 插件(plugin) | 一个 `.mgp` 包:`manifest.json` + `plugin.wasm` + 图标 |
| 来源(source) | 插件提供的音乐服务,例如「网易云音乐」。一个插件对应一个来源 |
| 能力(capability) | 插件声明实现的一组方法,例如 `search`、`stream`、`account` |
| 方法(method) | 宿主向插件发起的一次调用,例如 `search.query` |
| 宿主函数(host function) | 插件向宿主发起的一次调用,例如 `http.do` |
| 市场(market) | 官方的插件索引 `index.json`,由 `mygo-music/plugins` 的 CI 生成 |
| 会话(session) | 用户在某个来源的登录状态,存在宿主的 cookie 罐与钥匙串里,按插件隔离 |

## 1.4 仓库分工

```
mygo-music/mygo-music      宿主应用(AGPL-3.0)
mygo-music/plugin-sdk      本仓库:规范、Go 库、wazero 运行时、CLI、模板(Apache-2.0)
mygo-music/plugins         插件登记处:收录标准、PR 校验 CI、生成 index.json(Apache-2.0)
mygo-music/plugin-netease  网易云音乐插件,SDK 的参考实现(许可证由其作者定)
```

宿主依赖 `plugin-sdk/host` 来运行插件,插件依赖 `plugin-sdk/plugin` 来编写。**ABI 只有一份实现(`host/`)**,宿主和 CLI 的测试工具共用它,避免两边行为漂移。

## 1.5 架构

```
┌──────────────────────────── 宿主 ────────────────────────────┐
│  原生 UI  ←──  统一数据模型  ←──  插件运行时(wazero)         │
│  播放器:解码 · 缓存 · 淡入淡出 · 音量均衡 · 歌词 · 字幕(ASR)   │
│  系统钥匙串 · 数据目录 · 网络(权限校验)                       │
└───────────────▲─────────────────────────────┬───────────────┘
        方法调用 │ JSON                 宿主函数 │ JSON
   (search.query…)│                    (http.do…)│
┌───────────────┴─────────────────────────────▼───────────────┐
│  plugin.wasm(WASI reactor,沙箱:无文件系统、无套接字、无环境变量) │
└──────────────────────────────────────────────────────────────┘
```

要点:

1. **宿主发起,插件应答。** 插件不能主动改界面,只能响应方法调用,并通过宿主函数访问网络、存储、钥匙串。
2. **插件只返回数据。** 歌曲、歌单、分区、登录步骤都是数据;宿主决定怎么画。
3. **播放在宿主。** 插件只返回流地址(+请求头、格式、增益),宿主自己下载、解码、缓存、播放。
4. **实例无状态。** 插件进程内存只是缓存。任何会话、设备标识、偏好都存在宿主提供的 cookie 罐 / kv / secret 里。宿主可以随时丢弃并重建实例(超时、内存超限、并发扩容),插件不会感知到。

## 1.6 版本

- **`api`**:整数,契约的主版本。本规范是 `api: 1`。宿主声明自己支持的 `api` 集合;不在其中的插件拒绝加载。
- **兼容规则:** 在同一 `api` 内只做加法——新增可选字段、新增方法、新增能力。**双方都必须忽略未知字段**。需要破坏性修改时才升到 `api: 2`,宿主在一段过渡期内同时支持两个主版本。
- **`min_host`**:插件用到较新的宿主特性时,在 manifest 里声明最低宿主版本。
- 插件自己的 `version` 遵循 semver。

## 1.7 已定的决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 运行时用 **WASM(wazero,纯 Go,无 cgo)** | 一个文件跨平台;天然沙箱;网络可按域名白名单限制;适合「任何人提 PR」的开放市场 |
| D2 | SDK 与登记处用 **Apache-2.0**;宿主保持 AGPL-3.0 | 写插件不应被迫开源;宿主引用 Apache 库没有许可证冲突 |
| D3 | 网易云插件**进官方市场**,同时支持 **URL 安装** | 市场是发现入口;URL 安装给未收录或自行分发的插件 |
| D4 | ABI 用 **JSON 信封** | 任何能编译到 wasip1 的语言都能写插件;易调试。性能对「一次一个 API 请求」的负载足够 |
| D5 | **能力模型**,不是「插件种类」 | 以后加歌词源、记录听歌(scrobble)等,只是新增能力,不改架构 |
| D6 | 实例**无状态**,会话存宿主 | 取消、超时、并发都变简单(丢实例即可) |
| D7 | 插件**不自绘 UI**;页面用声明式分区 | 跨平台一致、安全、不拖慢渲染 |
| D8 | 全部改名,不考虑老用户的自动更新 | 产品改名为「MyGo 音乐」,模块、标识符、更新源一并迁移 |
| D9 | 不增加额外的签名与公证;**市场索引不签名** | 完整性靠 HTTPS、每版本固定的 sha256 与构建来源证明;宿主自身不做自动更新,只在设置里手动检查 GitHub Release |
| D10 | 多来源界面用**来源切换器**(09 号文档 §9.2) | 与现有界面几乎一致,复杂度最低;「搜索所有来源」以后可在其上加 |

## 1.8 待定 / 需要实测的事项

这些不影响文档评审,但会影响实现,需要在第 3 阶段开头用小实验确认:

| # | 事项 | 为什么要验证 |
|---|---|---|
| S1 | Go 1.27 `GOOS=wasip1 -buildmode=c-shared` 产出的 reactor 模块,在 wazero 下能否反复调用导出函数,且导出函数执行中调用阻塞的宿主函数 | ABI 的核心假设(§3.3)。若不成立,换成「每次调用新建实例」或改用 TinyGo |
| S2 | 带 `net/http` 与 TLS 相关包的 wasm 体积与冷编译耗时 | 决定是否在 SDK 里提供不依赖 `net/http` 的轻量 HTTP 客户端;决定是否必须使用 wazero 的磁盘编译缓存 |
| S3 | 网易云 eapi 所需的 AES-ECB、MD5、RSA 在 wasm 下的速度 | 预期无问题,但要量一下 |
| S4 | ~~多来源的界面形态~~ | **已定**:来源切换器(D10) |
| S5 | ~~`index.json` 是否签名~~;国内镜像 | 签名**已定**为不做(D9);镜像仍待定,见登记处的 `docs/index-format.md` |
